## Scope

The read-only Cockpit can now start from the current Control Workspace root with:

```bash
npx triad-plus cockpit
```

The command validates the exact current directory, binds only to loopback, and retains the one-time session URL. In safe local interactive desktop contexts it attempts to open a browser; use `--no-open` to suppress this behavior. `--control <path>` remains the explicit override. Cockpit stays in the foreground until stopped with Ctrl+C, without controlling agents or attesting live activity.

New-project setup offers explicitly numbered existing Git-root suggestions. Selecting a number or supplying a path is required; no product repository is selected silently. Invalid repository paths can be corrected at the prompt and a repository-plan preflight failure can be retried within the wizard. `init --host ... --control ...` installs adapter assets and does not by itself establish project readiness. Command errors are shorter and the `doctor` output explains when all adapters are being inspected.

## Deliberate boundaries

OpenCode does **not** gain a native `/cockpit` command: the available custom-command interface is prompt-backed and does not establish safe persistent-process lifecycle management. Use a separate terminal for the CLI Cockpit command.

This maintenance release introduces no live Control Room, no fourth agent, no Core governance change, no additional verifier attestations, and no automatic Reviewer approval. The Cockpit remains a read-only view of persisted evidence, not a host activity monitor. A declared `in_progress` state is not proof of liveness.

No changes to installation ownership semantics, remote binding, package runtime dependencies, or optional post-approval Evaluator+ behavior are intended.

## Release verification
