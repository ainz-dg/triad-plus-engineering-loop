# Triad+ 1.18.0 — release notes

**Publication history (recorded 17 October 2026):** v1.18.0 was published on
12 October 2026. The candidate wording and release-gate section below preserve
the original release notes and describe their historical preparation state.

**Version:** 1.18.0 (minor). These notes preserve the original release

## Summary

This release improves Reviewer-document findability in the read-only Cockpit
and makes human-readable Card and handoff reports more useful when canonical
evidence includes safe local artifact references. It preserves the distinction
between declared documents and validated review results, and between report
views and canonical control records.

## Cockpit Reviewer documents

- Attempt-local documents whose filenames identify them as reviews are
  surfaced within their matching Attempt, with their path and
  `agent-declared` provenance.
- The Cockpit says that the document is available but its verdict is **not
  attested**. It does not parse Markdown to derive a decision or validate a
  Reviewer identity.
- Card-level `.loop/reviews/` documents remain Card-level unless an existing
  validated binding says otherwise. Ambiguous filename matches remain
  unattributed, and the deterministic-driver Reviewer contract remains
  separate from host-governed documents.

## Human-readable report references

- Card and delivery reports preserve source-path identity while resolving
  relative references only when they identify one existing regular file across
  the declared project/worktree roots.
- Absolute references are linked only when the existing file and report output
  share a declared root. Generated links are relative to the report output and
  remain within that root.
- Missing, external, ambiguous, malformed, or out-of-root references remain
  plain redacted text. Symlink references that resolve outside the declared
  root are not linked.
- An available renderer still does not mean reports are automatically
  materialized. Report files are views derived from supplied context, not new
  canonical evidence or approval records.

## Breaking changes and migration

No breaking changes or migration are intended. The package keeps zero runtime
dependencies and requires Node.js 20 or newer.

## Limitations and deferred work

- Cockpit documents do not prove Reviewer identity or attest their verdicts.
- No host-governed attempt verdicts, automatic report generation, live
  multi-host dispatch, or Control Room integration are claimed.
- The accepted local-filesystem path-resolution TOCTOU limitation remains
  unresolved; use remains limited to trusted single-user local workspaces.
