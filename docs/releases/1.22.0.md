## What's new

- **Clearer onboarding and documentation policy.** The guides distinguish the first-run wizard's structural presence checks from `doctor` diagnostics and `triad-verify` gate evidence. The OpenCode walkthrough reflects the current Cockpit fixture, and review expectations now require a documentation-impact analysis.
- **Opt-in Codex and Hermes entries.** With explicit consent, installation can add user-level Codex `$triad` and Hermes `/triad` entries and bind a trusted global preflight to a canonical Control Workspace. The preflight is model-instructed validation, **not** a pre-LLM host-enforced security boundary. Full native Codex READY/BLOCKED behavior and Hermes native discovery are not proven.
- **Post-run PR planning.** The opt-in `triad-pr-plan` flow supports deterministic grouping, canonical dependency checks, byte-bound plans, explicit owner approval, drift checks, and draft-only PR creation. It does not generate source snapshots or schedule draft creation in-loop. Operators must prepare the approved snapshots and group worktrees, branches, and pushes. Automatic stacked PRs, merging, and cost reduction are not claimed.
- **Pre-run structure approval and multi-Card baselines.** The Orchestrator can obtain explicit approval for exact Card grouping and branch/worktree/base/remote bindings before implementation. Post-run verification refreshes canonical evidence; a Card's candidate check uses its own canonical baseline while group-level draft validation still requires the exact approved commits. Legacy post-run approval remains available.
