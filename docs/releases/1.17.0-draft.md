# Triad+ 1.17.0 — release notes draft (unpublished)

**Status:** local release-candidate readiness draft; not published. The proposed
SemVer is **1.17.0** (minor), subject to owner review and a separate release GO.

## Summary

This candidate packages the opt-in multi-adapter installation inventory and
its conservative lifecycle operations. Existing schema-v1 installations remain
readable; migration to schema v2 occurs only after an explicit successful
`adapter add`. The ordinary install flow remains unchanged.

## Breaking changes

None intended in this candidate. The multi-adapter inventory does not change
the existing default host selection or dispatch behavior.

## Migration

No migration is required to continue using an existing v1 installation. To add
a second project-local adapter, first review the dry run and then explicitly
apply `triad-plus adapter add <id> --control <path> --apply`. That operation
migrates the installation record to schema v2. Do not use `init` to modify a
workspace already recorded as multi-adapter. Global multi-adapter assets are
not supported.

## Limitations

- Adapter inventory/lifecycle is not per-Attempt host selection and does not
  provide automatic cross-attempt handoff. Attempt dispatch remains
  unsupported.
- A CLI being present, or an adapter being installed, does not prove host-native
  project-local discovery or end-to-end delegated execution. Codex and Hermes
  entry points remain limited/unproven; other host discovery must be reported
  only when actually observed.
- The accepted local-filesystem path-resolution TOCTOU limitation remains
  unresolved and is appropriate only for a trusted single-user local workspace.
- This draft makes no six-host runtime, paid-model, or native discovery claim.
