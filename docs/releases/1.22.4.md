# Triad+ 1.22.4

## Product changes

- Keep generated host assets loadable when requested role model IDs are invalid
  or unverified. `.triad-plus/team.json` preserves requested model/effort
  intent; generated agents use host/session defaults and do not apply role-level
  model routing in this release scope.
- Add guided first-entry readiness for models/defaults, mapped repositories,
  worktrees, PRD prerequisites, and explicit per-repository quality-gate
  consent. Dispatch and verifier checks bind approvals to current inputs.
- Discover quality-gate candidates from mapped repositories/worktrees as an
  inactive proposal. Discovery reads manifests and does not execute candidate
  commands or replace existing active gate files. Owner review is required
  before a selected gate is enabled.
- Add explicit Codex/Hermes global entry refresh with exact-path preview,
  current-state consent, backups, rollback, and fail-closed handling. Hermes
  named profiles keep skills in `HERMES_HOME` and use the canonical wrapper
  under `HOME/.hermes`.

## Validation scope and limits

- Package-tarball E2E acceptance demonstrated setup, guided consent, a useful
  `/triad` task, deterministic verifier/gate PASS, and separate Reviewer
  approval on OpenCode 1.19.3 with host-default `opencode/big-pickle`.
- The OpenCode Orchestrator, Developer, and Reviewer shared that host/session
  default. Per-role model or effort selection is not applied or verified.
- Six adapters are installable and have contract/fixture coverage; this release
  does not claim six native live sessions. Claude Code, Codex, Copilot,
  Antigravity, and Hermes native E2E sessions are not attested by this scope.
- The Reviewer approved the acceptance task on the first attempt; no rework
  cycle was exercised or tested.
- A gate without an optional `toolchain` binding can be explicitly approved,
  pass, and be recorded as `unbound`. This is supported legacy behavior. It
  means executable identity was not pinned; consent and verifier scope still
  apply, and the status does not establish that an arbitrary script body is
  safe or immutable.

The live acceptance was run against the v1.22.4 source tree before the package
version/documentation-only release preparation. Its local test tarball retained
the old `1.22.3` package metadata and is not a publishable `1.22.4` artifact.
The release-preparation PR separately records verification of the newly packed
`1.22.4` archive. No npm publication is implied by these notes.
